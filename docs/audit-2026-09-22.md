## GitHub Projects: the name, the ground, the rail

The section is called **GitHub Projects**, which is what it is: every word on a
card comes from a repository. It keeps the page's own ground — the module
background tried here was wrong and was taken out the moment it was seen.

Inside the pane a rail down the right says where the reader is: the marker's
height is the share of the list on screen, its distance from the top is the
progress. It sits in the pane's padding, so it takes no width from the grid and
two cards still fit in a row at 320 px.

It was a CSS scroll-driven animation first (`timeline-scope` on the deck,
`scroll-timeline` on the pane, `animation-timeline` on the marker), and that is
the version to prefer on paper: no JavaScript at all. It was removed after
measuring:

| Build                                | TBT       |
| ------------------------------------ | --------- |
| No rail                              | 3 ms      |
| Rail, scroll-driven, animating `top` | 94–137 ms |
| Rail, scroll-driven, transform only  | 85 ms     |
| Rail, passive listener (`useRail`)   | 1.5 ms    |

The browser resolves the scroll timeline during load whether or not anyone
scrolls the pane; the transform-only version proved the cost was not the
property being animated. A passive `scroll` listener that writes one custom
property on the rail itself costs nothing until the pane is scrolled: +159 B of
critical JavaScript for 84 ms of blocking time. The pane's scrollable length is
read on `ResizeObserver`, never per frame.

Without JavaScript the marker is absent (`[data-live]` is set by the hook) and
the pane still scrolls, still takes the keyboard, still has its focus ring.

## The CSS becomes Tailwind v4

Asked for as a framework, so that the page adheres to a style instead of being
retouched a detail at a time. Bootstrap was considered and not taken: ~25 KB
gzip and a visual language that would have to be overridden back to this one,
which is the opposite of the goal. Tailwind v4 emits only what the markup uses
and takes its scales from the tokens already here.

How it is arranged:

- **`theme.css` is the system.** `@theme` declares the 4px `--spacing` step,
  the typeface, the colour roles and the three breakpoints the page was already
  written to. `bg-surface` and `var(--color-surface)` are therefore the same
  colour by construction, not by coincidence. It also declares what the page
  repeats as utilities: `shell`, `section`, `mono`, `eyebrow`, `link`,
  `theme-shift`.
- **Layers decide who wins.** What is still hand-written sits in Tailwind's
  `base` and `components` layers, so a utility in the markup always beats it.
  Without that, unlayered CSS would win over every utility and the migration
  would be a specificity fight instead of a move.
- **What stayed in CSS** is what a utility should not carry: the pane's four
  background layers, the rail and its marker, the dot between technologies, the
  collapse bar, the research band's palette remap, the three dots on the paper
  preview, the underline inside the publication link, the back-to-top hover,
  the element defaults and the print stylesheet.

Two things the move taught, both measured rather than assumed:

- **An alias is substituted where it is declared.** `--accent: var(--color-accent)`
  on `:root` resolves there, so the research band remapping `--color-accent`
  changed the utilities and not the rules that still spell `--accent`: link text
  came out page-blue on navy, 1.47:1, and axe caught it at 980 px. The band now
  remaps both names, and the alias goes when the last rule that spells it does.
- **Class names are an interface.** `useDeck`, `useRail`, the print stylesheet
  and the tests all held the page by class. Where the name was a hook it stayed
  (and carries no screen styles); where the test was really asking about
  structure it now asks for that: the banner role, the nav's label, `article`,
  `h3`.

Result: hand-written CSS from about 1,600 lines to 942, of which 163 are print
and 150 are the system itself. The stylesheet ships at 9,109 B gzip against the
12,000 budget, up from 6,017: the reset and the tokens cost about 2 KB, and
every component's rules are now in the markup that uses them. The critical
JavaScript went the other way by about the same amount, 58,998 to 61,070 B
against the 65,000 ceiling, because the class lists are now in the markup and
the markup is in the bundle. Both budgets hold; `check` is green end to end,
with performance 0.99, accessibility 1, CLS 0 and TBT 0 on the run that
followed.

## What the UX review asked for, and what changed

Three things, 23 September.

**The pane is gone.** The projects were in a region with a scroll of its own:
a reader who reached the last one found the page still behind it, and no
styling makes an inner scroll say which of the two is moving. The list is the
page's now — transparent, no frame, no recessed ground — so reaching the last
project carries on into the next section. A test asserts it: nothing inside
`#work` may have `overflow-y: auto | scroll` with more content than room again.

**The rail stayed, and became honest.** It measures the page's scroll across
the list instead of a pane's: the marker's height is the share of the list on
screen, its offset the reader's position in it. `useRail` writes both in
pixels, so the stylesheet never divides by a custom property. It hides below
760 px, where there is no room beside the column, and where there is no
JavaScript.

**The page has a choreography.** A section rises 18 px and fades in as it is
reached, once, and the parts of a section follow one another 70 ms apart; the
heading's icon settles a beat behind its words; the menu underlines the section
being read (`useScrollSpy`, one observer on a band across the middle of the
viewport). Nothing is hidden waiting to be revealed: the stylesheet only names
an animation, so without JavaScript or with reduced motion everything is
already there at full opacity.

One measurement changed the design. Animating what is _already on screen_ at
load cost **95 ms** of blocking time against **0** without it. The first screen
now does not animate — which is also the right idea, since it was not arrived
at — and TBT came back to 2–9 ms.

## Research becomes Achievements, and the suite loses half its weight

**The section.** "Research" was a band of navy holding one paper, in a layout
of its own, and it read as an appendix. It is now **Achievements**: an entry in
the same grammar as a project — what this is and when, the title, the picture,
the sentence, the number that matters, the links — so the page has one object
from top to bottom, and the paper is the first of a list that can grow.

What the two widgets do not share is where they come from, and that is the
whole point of the split: a project is **fetched**, keyed by its repository and
kept level by `npm run sync`; an achievement is **asserted** in
`src/data/achievements.ts`, and every one of them carries an `evidence` link to
a record somebody else holds — a DOI, an archive, a release. The rule for
adding one is in that file: no record, no entry.

The grammar itself moved into `src/components/entry.ts`, so the two sections
cannot drift apart a utility at a time. One thing had to change there: a tall
picture spanning several grid rows sets their heights, which pulled the
sentence, the number and the links apart. Everything after the picture is now
one block — `display: contents` on a phone, the second column from 760 px — and
the entry went from 685 px to 564 px with nothing removed.

**The hero.** Less about the journal: the publication is one quiet line instead
of a filled band, and it names what was done rather than where it appeared.
Where "Current topics" listed three words that never changed, **Last updates**
now links the three repositories pushed most recently, straight from the
snapshot — the one part of the first screen that moves on its own.

**The tests.** From 30 to 15, deliberately.

What stayed is what nothing else can catch: axe at both ends of the responsive

## The order of the page, and which ground belongs to what

**Projects first, achievements after.** The work comes before the record of it.

**The grounds alternate between widgets, not inside them.** Zebra striping the
entries was tried and taken out within the hour: inside a widget every entry is
the same kind of thing, so tinting every other one says something untrue about
them, and the negative margins the bands needed pushed the document past the
viewport at 1440 px. What alternates now is the widget: GitHub Projects sits on
the page's own ground, Achievements on the wash as a rounded module, About back
on the page. A hairline separates entries within a widget, a change of ground
separates one widget from the next.

**The list says it is open.** The second entry in Achievements is a place kept
for the next one: a small dashed block, no picture, no figure, no link, because
there is nothing yet to show or to check. It is a separate type in
`achievements.ts` (`Upcoming`), not an achievement with empty fields, so the
compiler still requires every real entry to carry its evidence.

## A regression the migration hid, and the desktop layout

**The page column had stopped narrowing.** `.shell` is capped at 960 px above
1000 px so everything sits on one measure near the middle of the window. When
it became a Tailwind utility, the two media queries that set those widths
stayed behind in `base.css` — and a utility beats a class, so they did nothing.
Measured: at 1,680 px the column was **1,640 px** wide and the category and the
date at the two ends of a project's first line were **1,294 px** apart. That is
what "non c'è uniformità" was pointing at, and it was a bug rather than a
choice.

The widths live in the utility now, and the column is 350 / 836 / 960 px at
390 / 900 / 1,680. The date also stopped being pushed to the far edge of the
line: at 960 px that put it 614 px from the words it dates, which is distance,
not alignment. It follows the category.

**The visual baselines are down to one capture per scene**, the desktop layout
in the dark palette, where the wide grid and the redefined colours are on
screen together. Five baselines, not twenty. They run in six seconds; their
real cost is that every deliberate change asks a human to look at a diff, and
that cost is per baseline.

## The page gets a pulse

Four public sources, all free, all read at build time and committed as a
snapshot. The page still calls nobody; the footer now says both halves of that
out loud — "Read from GitHub, Crossref and PyPI on 23 Sep 2026" beside "no
third-party requests".

| Source        | Endpoint                      | What it added                                   |
| ------------- | ----------------------------- | ----------------------------------------------- |
| GitHub        | `/repos/…/releases/latest`    | `v2.0.1 · 16 Jan 2026` on a project             |
| GitHub        | `/repos/…/actions/runs`       | `checks passing`, from the last completed run   |
| GitHub        | `/repos/…/commits?per_page=1` | the date under "Last updates" in the hero       |
| GitHub        | `/repos/…/languages`          | the technologies of a project that asserts none |
| Crossref      | `/works/<doi>`                | `Cited 2 times · Crossref` on the achievement   |
| PyPI          | `/pypi/<name>/json`           | `lecturize 1.1.0 on PyPI`                       |
| pypistats.org | `/packages/<name>/recent`     | installs last month, when it answers            |

Three things the wiring taught:

- **One set of headers does not fit four hosts.** Sending
  `Accept: application/vnd.github+json` to Crossref returns 406. GitHub's
  headers now go only to GitHub.
- **A 404 is an answer.** `releases/latest` returns 404 for a repository with
  no release, which is most of them; logging that as a failure made a healthy
  sync look broken.
- **A source that is down must not empty the page.** Every field falls back to
  the value already in the snapshot, and the script says on stderr which ones
  it kept. Running it locally against the unauthenticated rate limit — 60 an
  hour, against 11 repositories × 4 calls — exercised exactly that path.

Dates are absolute, never "two days ago": the page is rendered at build and
again in the browser, and a relative label would disagree with itself between
the two and go stale in the HTML the moment the build ended.

## Signals on a project, as symbols

The fetched line under a project is now a row of small chips, each one a signal
a developer reads in a second and no sentence conveys as fast: the licence, the
stars, the last release with its date, the conclusion of the last CI run with a
tick or a cross, the package and its version on the registry, and when the code
last moved. Any of them can be missing — most repositories have no release and
no package — and the line simply gets shorter.

Two of them were removed on sight. **The primary language**, because GitHub
counts languages by bytes and that makes a Scala project "Jupyter Notebook";
the line above already says what the project is written in, and says it right.
And the second date needed a word: two dates on one line, one for the version
that shipped and one for the last commit, are told apart by "updated" rather
than by their icons alone.

`license` and `forks` were added to the sync in the same pass but are not in
the snapshot yet: the unauthenticated rate limit was spent. They appear at the
next run of the Action, and until then the chip is simply absent — which is the
behaviour every field here has by design.

One number to watch: the six icons cost about 850 B gzip, and the critical
JavaScript is at **63,383 B of 65,000**. The next thing added to this page has
to earn its bytes, or the icons become one inline sprite.

## Three registers, so the eye can sort them

An entry now says three different kinds of thing, and they look like three
different kinds of thing:

1. **The prose** — the sentence from the repository, the label under the
   number — in muted ink.
2. **What it is built with** — filled, rounded tags. The fill is
   `color-mix(in srgb, var(--color-ink) 7%, transparent)`, a percentage of ink
   rather than a colour, so one tag sits correctly on the page's ground and on
   a module's wash without knowing which it is on. They are filled, where the
   index pills above a list are outlined and colour on hover: those are links,
   these are not, and they must not look alike.
3. **What was fetched** — the licence, the stars, the release, the CI run, the
   registry, the last commit — in a colour of their own, a green-slate
   `--color-signal` that is neither ink nor accent. It says "state", which is
   what they all are, and it separates what the page was told from what the
   page asserts. On the achievement, the one fetched fact among asserted ones
   — "Cited 2 times · Crossref" — is a tag in that same green, so the
   distinction survives even inside a single list.

Contrast measured before it shipped, and axe agrees at both ends: 5.9:1 on the
page's ground and 5.5:1 on the wash in light, 8:1 and 6.5:1 in dark.

## The photograph becomes a drawing

David now comes through a tear in the page, waving: a half figure, flat
cartoon, drawn as an inline SVG.

Inline, because that is what lets it be made of the page's own tokens — the
paper is `--color-bg`, the line is `--color-ink`, the shirt is
`--color-surface` — so it inverts with the theme instead of being a picture of
a light page sitting on a dark one. Two colours are its own and not the page's:
`--skin`, and `--hair`, because hair made of ink would inherit the dark theme's
near-white and he would go grey at sunset. The eyes, the brows and the nose
follow the hair for the same reason; the teeth are white in both themes.

What makes him read as coming _through_ the page: the head and the raised arm
are drawn above the frame, the torso is clipped inside it, the torn edge casts
a gradient of shadow into the hole rather than a flat strip with an edge of its
own, two flaps of paper are lifted towards the reader, and the arm is drawn
last so it passes in front of everything. The wave turns the arm about the
shoulder three times and stops — a hand waving for ever is a novelty, one that
waves when you arrive is a greeting — and it waves again on hover. The global
reduced-motion rule already switches it off.

**What it cost, and what paid for it.** The drawing is about 800 B gzip of
critical JavaScript, which took the budget to 64,254 of 65,000 — 746 B of
headroom, which is not a margin. So the seven marks on the fetched line came
out of the icon library and into `Glyph.tsx`: the same shapes in the same
visual language, hand-written, for about a tenth of the bytes. The library
stays for everything else; this was simply the wrong place to spend. The
photograph's four WebP variants left `public/` with it.

Result: **63,768 B** critical JavaScript, LCP 1.96 s, and one fewer request on
the first screen — the portrait used to be the mobile LCP element and is now
part of the document.

## Two themes with names: Solarized Light and One Dark

The palette is no longer a set of greys chosen here. The light theme is
**Solarized Light** by its own names — base3 is the page, base2 the modules,
base02 the text — and the dark theme is **One Dark**: `#282c34` the ground,
`#3e4451` the lines, `#abb2bf` the foreground, its blue and its green used as
they are.

Four values are not the schemes' own, and each has a reason in the file:

| Token                     | Value                             | Why it is not the scheme's                                        |
| ------------------------- | --------------------------------- | ----------------------------------------------------------------- |
| `--color-surface` (light) | base3 lifted                      | Cards sit on the page, and base3 is already the page              |
| `--color-accent` (light)  | Solarized blue darkened           | His blue on base3 is 3.4:1; links here are body text and need 4.5 |
| `--color-signal` (light)  | Solarized green darkened          | 3.0:1 as published; 4.7:1 on the darkest ground it lands on       |
| `--color-muted` (dark)    | One Dark's comment grey lightened | 2.3:1 is a comment in an editor and unreadable as a caption       |

One of those was found rather than predicted. The green passed on the page and
on the wash and still failed at 320 px: axe measured it at **4.09:1** on a
_tag's own fill_, which is 7% ink over the wash and darker than either ground
I had checked. Darkened once more, it passes everywhere it can land.

The print stylesheet was overriding colours that no longer exist — it still
spelled the pre-Tailwind alias names, so a printed page would have come out
cream or, worse, in One Dark. It now overrides the roles themselves, and it
sits outside every layer, which is what lets it beat a colour set by a utility
in the markup.

## The theme control looks like a control

It is the only switch on the page, so it now reads as one: a disc, a ring set
a little away from it, a hair of depth beneath, and a press.

The whole control is one colour: Solarized's red on the warm theme, One Dark's
blue on the cold one, in the glyph, in the ring around it and in the halo under
both. The ring is a ring rather than a border so it can sit off the edge, which
is what makes it read as wrapped around the control instead of belonging to it,
and it widens on hover.

The halo is the invitation, and it is the one thing on this page that moves
without being scrolled to: a 2.6 s breath between 10% and 26% opacity on a
44 px control, behind the disc so it never tints the ground the glyph is
measured against. Reduced motion removes it, as it removes everything else
here.

Contrast, since a coloured glyph still has to be seen: 4.5:1 on the surface and
3.8:1 on the wash it sits on when hovered in light, 4.8:1 in dark. An icon
needs 3.

Three passes to get there, and the two discarded ones are worth recording: a
conic gradient through Solarized's warm end (pretty, not what was asked), and
the ring in the theme's own ground darkened (correct to the letter, dead to
look at).

## What one visit costs

The page now says what it weighs in the world: **0.018 g CO₂ a visit, rating
A+**, from Website Carbon, for the 171 KB the home page actually transfers.

It is measured in `scripts/performance.mjs` rather than in the sync, because it
depends on the build and not on the time of day — a page's footprint changes
when the page changes, not when the clock moves. The arithmetic is theirs (the
Sustainable Web Design model and their coefficients), the bytes are Lighthouse's
`total-byte-weight` from the run the figure was taken from, and the footer
credits them by name, like every other fetched figure here. If they do not
answer, the previous number stands with its own date.

It sits beside "no analytics, no cookies, no third-party requests", which is
the right company for it: this is the same claim, expressed as a quantity that
someone else computed.

## About is gone

The page is now the hero, GitHub Projects, Achievements and Contact. The About
section held a paragraph of LinkedIn wording and the two degrees, and both are
said better elsewhere: the degrees are on the CV, which is the first thing the
hero offers, and the sentence about what he is doing now is in the hero's own

The degrees stay in `profile.ts` because `Resume.tsx` prints them. The

## The menu never marked the last section

Reported, reproduced, fixed. The indicator was an IntersectionObserver watching
a band across the middle of the viewport, and it could not light Contact:
Contact is shorter than that band, and at the bottom of the page — where the
scroll stops — the band lies over the footer, so no section is inside it at
all. A reader who got to the end saw nothing marked, which is worse than
marking nothing at all: the menu looks broken.

It reads position now. The current section is the last one whose top has passed
a line a third of the way down the viewport, and at the bottom of the document
it is the last section, because that is what the reader has arrived at whether
or not it is tall enough to reach the line. One passive listener, coalesced
into a frame; the section tops are measured on resize, not per frame.

A test holds it: scroll to the bottom, Contact is `aria-current`. That is the
case a person reported, so that is the case the suite now owns.

## The UI review, carried out

Nine findings from the review of 23 September, in three passes. What each one
cost and what it moved:

**The system.** Nine font sizes became five, declared once in `@theme` and far
enough apart to be told apart: 12 for what was fetched, 14 for the text, 16 for
a lead, 21 for a title, 34 for the name. Everything Tailwind ships above them is
`initial`, so a sixth size is a decision rather than an accident. The figure in
an entry, which was 27 px against its title's 21, is one step under the title:
a portfolio is scanned by name, and the eye was reading the numbers first. The
fetched signals gave back their green — a third hue for the least important
class of information on the page — and kept it only where the colour _is_ the
information, on a build that passed. The theme control stopped breathing.

**The first impression.** The hero led with a degree and never said what he
builds; it now opens with one sentence naming what the five projects under it
are, which a reader can check by scrolling. "Last updates" left the first
screen for the section it is about. The hero closes on its actions instead of
carrying a section's padding, and at 1440 the first project is now inside the
first screen, where the fold used to land in the gap. Contact answers the
question it is asked: "from when" was the second half of a sentence about
e-mail and is now the first line, in ink.

**The density, and the honest part.** The rail is gone. It was a window's
indicator and the window went away in the morning; since then it had been
saying what the browser's own scrollbar says, two centimetres to its left,
while the pills above already name the project in view. The covers are 16:9 on

- Three featured projects on a phone and two behind a control (−1,000 px).
- "Also on GitHub" as a native disclosure under 760 px (−400 px).

under the 24 px a target needs. WCAG 2.2's target size is the check that keeps

## The sun and the moon break

Every press of the theme control switches the theme and does a little more
damage to what it shows: whole, cracked, broken in two. The third press puts it
back together, which is the joke, and also the only ending that does not leave
a visitor stuck with a ruin. Six presses are a full turn of both bodies.

The two glyphs are drawn here rather than imported, because the library has one
sun and one moon and both are in one piece — so this also took the last two
icons out of the bundle. The crack is not one drawing used twice: the sun's
disc is eight units across and the crescent is three times that, so each has
its own, at the same angle and with the same kink, which is what makes the
damage read as one idea. A break throws off two shards and takes rays with it.

It starts whole on every visit, which is what the prerendered HTML contains,
so there is nothing to hydrate around and the visual baseline stays
deterministic. The glyph is keyed by its condition, so React replaces it on
every press and the hit animation runs again; reduced motion removes the shake
and keeps the damage.

A unit test holds the whole cycle: six presses, six distinct glyphs, and the
seventh is the first again.

It is a small joke on a page with none, and that is the argument for it: a
portfolio that is correct everywhere and surprising nowhere is a document.

## Compact, cased, gold, and a borrowed line

**The picture has a case.** A clip with the browser's controls under it and

**The control is gold.** Solarized's yellow two steps down, 4.1:1 on the

Page height, phone: **8.2 screens this morning, 7.0 now**, with the same

# Expression pass and its reversal, same day

The content pass above made the page accurate. What followed tried to make it
personal, in three rounds, and most of the third and part of the first were
taken out again the same afternoon on David's instruction. This section records
what stayed, what went, and why, because the working tree shows only the result.

## What stayed

**The wordmark balances.** An inverted pendulum: gravity pushes `dc.` away from
upright, a controller pushes back harder and damps what is left, a scroll tips

the rate are below what a screen could show.

**The state space closes as you scroll.** `43M → 32` is six orders of magnitude
and two tokens cannot carry that. The bar under the number is that range on a log
scale, closed by the visitor's own scroll. It only ever closes.

**Experience is gone**, on David's instruction, and later in the day so was the

## What the checks caught, and is worth keeping

- The whole Playwright suite runs under `prefers-reduced-motion: reduce`, set in
  `playwright.config.ts`: nothing moves in any browser test, and that, more than
  any waiting, is what keeps the visual baselines still.
- The fingerprint tool had been broken since the September content pass, hovering
  a class that no longer existed. Fixed; it then proved a refactor of the motion
  code changed nothing before that code was itself removed.
- Moving `position: relative` from the scroll container to a wrapper around it
  let the visually hidden text inside the cards' links, which is absolutely
  positioned, resolve outside the clip: the document grew by the height of the
  hidden list. Found by bisection in the page (`contain: paint` fixed it,
  `overflow: clip` did not), fixed by positioning the container again.
- A custom property written on `:root` per frame is a full-document style
  invalidation; a layout read inside a frame loop that also writes transforms is a
  forced layout per frame. Both were measured, not guessed.

## GitHub Projects: the name, the ground, the rail

The section is called **GitHub Projects**, which is what it is: every word on a
card comes from a repository. It keeps the page's own ground — the module
background tried here was wrong and was taken out the moment it was seen.

Inside the pane a rail down the right says where the reader is: the marker's
height is the share of the list on screen, its distance from the top is the
progress. It sits in the pane's padding, so it takes no width from the grid and
two cards still fit in a row at 320 px.

It was a CSS scroll-driven animation first (`timeline-scope` on the deck,
`scroll-timeline` on the pane, `animation-timeline` on the marker), and that is
the version to prefer on paper: no JavaScript at all. It was removed after
measuring:

| Build                                | TBT       |
| ------------------------------------ | --------- |
| No rail                              | 3 ms      |
| Rail, scroll-driven, animating `top` | 94–137 ms |
| Rail, scroll-driven, transform only  | 85 ms     |
| Rail, passive listener (`useRail`)   | 1.5 ms    |

The browser resolves the scroll timeline during load whether or not anyone
scrolls the pane; the transform-only version proved the cost was not the
property being animated. A passive `scroll` listener that writes one custom
property on the rail itself costs nothing until the pane is scrolled: +159 B of
critical JavaScript for 84 ms of blocking time. The pane's scrollable length is
read on `ResizeObserver`, never per frame.

Without JavaScript the marker is absent (`[data-live]` is set by the hook) and
the pane still scrolls, still takes the keyboard, still has its focus ring.

## The featured projects stop being cards

They are entries in a list now, in the language of "Also on GitHub" under them:
a hairline between one and the next, no box, no ground of their own. Inside an
entry the order is the category and the year, the title, **the picture**, the
sentence from GitHub, the figure, the technologies, the links. The picture is
capped at 20 rem: it fills the entry on a phone and stops there on a desktop,
where the sentence and everything after it sit beside it rather than leaving
half the row empty.

What this removed: the folder chrome and its tab, the subgrid that lined two
tiles up with each other, the two-column grid, and the two-line clamps on the
title and the sentence — a tile had to cut them short, an entry has the width
to show them. The layout test changed with it: it asserted two tiles to a row,
and now asserts one entry under another, the picture between the title and the
sentence, and the cap.

## The CSS becomes Tailwind v4

Asked for as a framework, so that the page adheres to a style instead of being
retouched a detail at a time. Bootstrap was considered and not taken: ~25 KB
gzip and a visual language that would have to be overridden back to this one,
which is the opposite of the goal. Tailwind v4 emits only what the markup uses
and takes its scales from the tokens already here.

How it is arranged:

- **`theme.css` is the system.** `@theme` declares the 4px `--spacing` step,
  the typeface, the colour roles and the three breakpoints the page was already
  written to. `bg-surface` and `var(--color-surface)` are therefore the same
  colour by construction, not by coincidence. It also declares what the page
  repeats as utilities: `shell`, `section`, `mono`, `eyebrow`, `link`,
  `theme-shift`.
- **Layers decide who wins.** What is still hand-written sits in Tailwind's
  `base` and `components` layers, so a utility in the markup always beats it.
  Without that, unlayered CSS would win over every utility and the migration
  would be a specificity fight instead of a move.
- **What stayed in CSS** is what a utility should not carry: the pane's four
  background layers, the rail and its marker, the dot between technologies, the
  collapse bar, the research band's palette remap, the three dots on the paper
  preview, the underline inside the publication link, the back-to-top hover,
  the element defaults and the print stylesheet.

Two things the move taught, both measured rather than assumed:

- **An alias is substituted where it is declared.** `--accent: var(--color-accent)`
  on `:root` resolves there, so the research band remapping `--color-accent`
  changed the utilities and not the rules that still spell `--accent`: link text
  came out page-blue on navy, 1.47:1, and axe caught it at 980 px. The band now
  remaps both names, and the alias goes when the last rule that spells it does.
- **Class names are an interface.** `useDeck`, `useRail`, the print stylesheet
  and the tests all held the page by class. Where the name was a hook it stayed
  (and carries no screen styles); where the test was really asking about
  structure it now asks for that: the banner role, the nav's label, `article`,
  `h3`.

Result: hand-written CSS from about 1,600 lines to 942, of which 163 are print
and 150 are the system itself. The stylesheet ships at 9,109 B gzip against the
12,000 budget, up from 6,017: the reset and the tokens cost about 2 KB, and
every component's rules are now in the markup that uses them. The critical
JavaScript went the other way by about the same amount, 58,998 to 61,070 B
against the 65,000 ceiling, because the class lists are now in the markup and
the markup is in the bundle. Both budgets hold; `check` is green end to end,
with performance 0.99, accessibility 1, CLS 0 and TBT 0 on the run that
followed.

## What the UX review asked for, and what changed

Three things, 23 September.

**The pane is gone.** The projects were in a region with a scroll of its own:
a reader who reached the last one found the page still behind it, and no
styling makes an inner scroll say which of the two is moving. The list is the
page's now — transparent, no frame, no recessed ground — so reaching the last
project carries on into the next section. A test asserts it: nothing inside
`#work` may have `overflow-y: auto | scroll` with more content than room again.

**The rail stayed, and became honest.** It measures the page's scroll across
the list instead of a pane's: the marker's height is the share of the list on
screen, its offset the reader's position in it. `useRail` writes both in
pixels, so the stylesheet never divides by a custom property. It hides below
760 px, where there is no room beside the column, and where there is no
JavaScript.

**The page has a choreography.** A section rises 18 px and fades in as it is
reached, once, and the parts of a section follow one another 70 ms apart; the
heading's icon settles a beat behind its words; the menu underlines the section
being read (`useScrollSpy`, one observer on a band across the middle of the
viewport). Nothing is hidden waiting to be revealed: the stylesheet only names
an animation, so without JavaScript or with reduced motion everything is
already there at full opacity.

One measurement changed the design. Animating what is _already on screen_ at
load cost **95 ms** of blocking time against **0** without it. The first screen
now does not animate — which is also the right idea, since it was not arrived
at — and TBT came back to 2–9 ms.

## Research becomes Achievements, and the suite loses half its weight

**The section.** "Research" was a band of navy holding one paper, in a layout
of its own, and it read as an appendix. It is now **Achievements**: an entry in
the same grammar as a project — what this is and when, the title, the picture,
the sentence, the number that matters, the links — so the page has one object
from top to bottom, and the paper is the first of a list that can grow.

What the two widgets do not share is where they come from, and that is the
whole point of the split: a project is **fetched**, keyed by its repository and
kept level by `npm run sync`; an achievement is **asserted** in
`src/data/achievements.ts`, and every one of them carries an `evidence` link to
a record somebody else holds — a DOI, an archive, a release. The rule for
adding one is in that file: no record, no entry.

The grammar itself moved into `src/components/entry.ts`, so the two sections
cannot drift apart a utility at a time. One thing had to change there: a tall
picture spanning several grid rows sets their heights, which pulled the
sentence, the number and the links apart. Everything after the picture is now
one block — `display: contents` on a phone, the second column from 760 px — and
the entry went from 685 px to 564 px with nothing removed.

**The hero.** Less about the journal: the publication is one quiet line instead
of a filled band, and it names what was done rather than where it appeared.
Where "Current topics" listed three words that never changed, **Last updates**
now links the three repositories pushed most recently, straight from the
snapshot — the one part of the first screen that moves on its own.

**The tests.** From 30 to 15, deliberately.

| Suite      | Before           | After  | What went                                                                                                                                                                                     |
| ---------- | ---------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Playwright | 18               | 8      | The 5×2 matrix ran the same stylesheet ten times; its two edges (320 light, 1440 dark) stayed. The choreography test went: motion is an enhancement, and nothing is lost when it does not run |
| Visual     | 4 (20 baselines) | 2 (10) | One phone in light, one desktop in dark                                                                                                                                                       |
| Vitest     | 8                | 5      | Two tested wording the content pass rewrites anyway; one tested a control the keyboard test already walks                                                                                     |

What stayed is what nothing else can catch: axe at both ends of the responsive
system, the page readable without JavaScript and at 200% text, the pictures
resolving and the clips fetching nothing before they are played, the CV and the
case study whole and printable, no mojibake or foreign name on any page, and
the promise in the footer — no third-party request. `npm run check` no longer
runs the visual baselines either: they are platform-specific, and they belong
to `check:visual`, on demand.

## The order of the page, and which ground belongs to what

**Projects first, achievements after.** The work comes before the record of it.

**The grounds alternate between widgets, not inside them.** Zebra striping the
entries was tried and taken out within the hour: inside a widget every entry is
the same kind of thing, so tinting every other one says something untrue about
them, and the negative margins the bands needed pushed the document past the
viewport at 1440 px. What alternates now is the widget: GitHub Projects sits on
the page's own ground, Achievements on the wash as a rounded module, About back
on the page. A hairline separates entries within a widget, a change of ground
separates one widget from the next.

**The list says it is open.** The second entry in Achievements is a place kept
for the next one: a small dashed block, no picture, no figure, no link, because
there is nothing yet to show or to check. It is a separate type in
`achievements.ts` (`Upcoming`), not an achievement with empty fields, so the
compiler still requires every real entry to carry its evidence.

## A regression the migration hid, and the desktop layout

**The page column had stopped narrowing.** `.shell` is capped at 960 px above
1000 px so everything sits on one measure near the middle of the window. When
it became a Tailwind utility, the two media queries that set those widths
stayed behind in `base.css` — and a utility beats a class, so they did nothing.
Measured: at 1,680 px the column was **1,640 px** wide and the category and the
date at the two ends of a project's first line were **1,294 px** apart. That is
what "non c'è uniformità" was pointing at, and it was a bug rather than a
choice.

The widths live in the utility now, and the column is 350 / 836 / 960 px at
390 / 900 / 1,680. The date also stopped being pushed to the far edge of the
line: at 960 px that put it 614 px from the words it dates, which is distance,
not alignment. It follows the category.

**The visual baselines are down to one capture per scene**, the desktop layout
in the dark palette, where the wide grid and the redefined colours are on
screen together. Five baselines, not twenty. They run in six seconds; their
real cost is that every deliberate change asks a human to look at a diff, and
that cost is per baseline.

## The page gets a pulse

Four public sources, all free, all read at build time and committed as a
snapshot. The page still calls nobody; the footer now says both halves of that
out loud — "Read from GitHub, Crossref and PyPI on 23 Sep 2026" beside "no
third-party requests".

| Source        | Endpoint                      | What it added                                   |
| ------------- | ----------------------------- | ----------------------------------------------- |
| GitHub        | `/repos/…/releases/latest`    | `v2.0.1 · 16 Jan 2026` on a project             |
| GitHub        | `/repos/…/actions/runs`       | `checks passing`, from the last completed run   |
| GitHub        | `/repos/…/commits?per_page=1` | the date under "Last updates" in the hero       |
| GitHub        | `/repos/…/languages`          | the technologies of a project that asserts none |
| Crossref      | `/works/<doi>`                | `Cited 2 times · Crossref` on the achievement   |
| PyPI          | `/pypi/<name>/json`           | `lecturize 1.1.0 on PyPI`                       |
| pypistats.org | `/packages/<name>/recent`     | installs last month, when it answers            |

Three things the wiring taught:

- **One set of headers does not fit four hosts.** Sending
  `Accept: application/vnd.github+json` to Crossref returns 406. GitHub's
  headers now go only to GitHub.
- **A 404 is an answer.** `releases/latest` returns 404 for a repository with
  no release, which is most of them; logging that as a failure made a healthy
  sync look broken.
- **A source that is down must not empty the page.** Every field falls back to
  the value already in the snapshot, and the script says on stderr which ones
  it kept. Running it locally against the unauthenticated rate limit — 60 an
  hour, against 11 repositories × 4 calls — exercised exactly that path.

Dates are absolute, never "two days ago": the page is rendered at build and
again in the browser, and a relative label would disagree with itself between
the two and go stale in the HTML the moment the build ended.

## Signals on a project, as symbols

The fetched line under a project is now a row of small chips, each one a signal
a developer reads in a second and no sentence conveys as fast: the licence, the
stars, the last release with its date, the conclusion of the last CI run with a
tick or a cross, the package and its version on the registry, and when the code
last moved. Any of them can be missing — most repositories have no release and
no package — and the line simply gets shorter.

Two of them were removed on sight. **The primary language**, because GitHub
counts languages by bytes and that makes a Scala project "Jupyter Notebook";
the line above already says what the project is written in, and says it right.
And the second date needed a word: two dates on one line, one for the version
that shipped and one for the last commit, are told apart by "updated" rather
than by their icons alone.

`license` and `forks` were added to the sync in the same pass but are not in
the snapshot yet: the unauthenticated rate limit was spent. They appear at the
next run of the Action, and until then the chip is simply absent — which is the
behaviour every field here has by design.

One number to watch: the six icons cost about 850 B gzip, and the critical
JavaScript is at **63,383 B of 65,000**. The next thing added to this page has
to earn its bytes, or the icons become one inline sprite.

## Three registers, so the eye can sort them

An entry now says three different kinds of thing, and they look like three
different kinds of thing:

1. **The prose** — the sentence from the repository, the label under the
   number — in muted ink.
2. **What it is built with** — filled, rounded tags. The fill is
   `color-mix(in srgb, var(--color-ink) 7%, transparent)`, a percentage of ink
   rather than a colour, so one tag sits correctly on the page's ground and on
   a module's wash without knowing which it is on. They are filled, where the
   index pills above a list are outlined and colour on hover: those are links,
   these are not, and they must not look alike.
3. **What was fetched** — the licence, the stars, the release, the CI run, the
   registry, the last commit — in a colour of their own, a green-slate
   `--color-signal` that is neither ink nor accent. It says "state", which is
   what they all are, and it separates what the page was told from what the
   page asserts. On the achievement, the one fetched fact among asserted ones
   — "Cited 2 times · Crossref" — is a tag in that same green, so the
   distinction survives even inside a single list.

Contrast measured before it shipped, and axe agrees at both ends: 5.9:1 on the
page's ground and 5.5:1 on the wash in light, 8:1 and 6.5:1 in dark.

## The photograph becomes a drawing

David now comes through a tear in the page, waving: a half figure, flat
cartoon, drawn as an inline SVG.

Inline, because that is what lets it be made of the page's own tokens — the
paper is `--color-bg`, the line is `--color-ink`, the shirt is
`--color-surface` — so it inverts with the theme instead of being a picture of
a light page sitting on a dark one. Two colours are its own and not the page's:
`--skin`, and `--hair`, because hair made of ink would inherit the dark theme's
near-white and he would go grey at sunset. The eyes, the brows and the nose
follow the hair for the same reason; the teeth are white in both themes.

What makes him read as coming _through_ the page: the head and the raised arm
are drawn above the frame, the torso is clipped inside it, the torn edge casts
a gradient of shadow into the hole rather than a flat strip with an edge of its
own, two flaps of paper are lifted towards the reader, and the arm is drawn
last so it passes in front of everything. The wave turns the arm about the
shoulder three times and stops — a hand waving for ever is a novelty, one that
waves when you arrive is a greeting — and it waves again on hover. The global
reduced-motion rule already switches it off.

**What it cost, and what paid for it.** The drawing is about 800 B gzip of
critical JavaScript, which took the budget to 64,254 of 65,000 — 746 B of
headroom, which is not a margin. So the seven marks on the fetched line came
out of the icon library and into `Glyph.tsx`: the same shapes in the same
visual language, hand-written, for about a tenth of the bytes. The library
stays for everything else; this was simply the wrong place to spend. The
photograph's four WebP variants left `public/` with it.

Result: **63,768 B** critical JavaScript, LCP 1.96 s, and one fewer request on
the first screen — the portrait used to be the mobile LCP element and is now
part of the document.

## Two themes with names: Solarized Light and One Dark

The palette is no longer a set of greys chosen here. The light theme is
**Solarized Light** by its own names — base3 is the page, base2 the modules,
base02 the text — and the dark theme is **One Dark**: `#282c34` the ground,
`#3e4451` the lines, `#abb2bf` the foreground, its blue and its green used as
they are.

Four values are not the schemes' own, and each has a reason in the file:

| Token                     | Value                             | Why it is not the scheme's                                        |
| ------------------------- | --------------------------------- | ----------------------------------------------------------------- |
| `--color-surface` (light) | base3 lifted                      | Cards sit on the page, and base3 is already the page              |
| `--color-accent` (light)  | Solarized blue darkened           | His blue on base3 is 3.4:1; links here are body text and need 4.5 |
| `--color-signal` (light)  | Solarized green darkened          | 3.0:1 as published; 4.7:1 on the darkest ground it lands on       |
| `--color-muted` (dark)    | One Dark's comment grey lightened | 2.3:1 is a comment in an editor and unreadable as a caption       |

One of those was found rather than predicted. The green passed on the page and
on the wash and still failed at 320 px: axe measured it at **4.09:1** on a
_tag's own fill_, which is 7% ink over the wash and darker than either ground
I had checked. Darkened once more, it passes everywhere it can land.

The print stylesheet was overriding colours that no longer exist — it still
spelled the pre-Tailwind alias names, so a printed page would have come out
cream or, worse, in One Dark. It now overrides the roles themselves, and it
sits outside every layer, which is what lets it beat a colour set by a utility
in the markup.

## The theme control looks like a control

It is the only switch on the page, so it now reads as one: a disc, a ring set
a little away from it, a hair of depth beneath, and a press.

The whole control is one colour: Solarized's red on the warm theme, One Dark's
blue on the cold one, in the glyph, in the ring around it and in the halo under
both. The ring is a ring rather than a border so it can sit off the edge, which
is what makes it read as wrapped around the control instead of belonging to it,
and it widens on hover.

The halo is the invitation, and it is the one thing on this page that moves
without being scrolled to: a 2.6 s breath between 10% and 26% opacity on a
44 px control, behind the disc so it never tints the ground the glyph is
measured against. Reduced motion removes it, as it removes everything else
here.

Contrast, since a coloured glyph still has to be seen: 4.5:1 on the surface and
3.8:1 on the wash it sits on when hovered in light, 4.8:1 in dark. An icon
needs 3.

Three passes to get there, and the two discarded ones are worth recording: a
conic gradient through Solarized's warm end (pretty, not what was asked), and
the ring in the theme's own ground darkened (correct to the letter, dead to
look at).

## What one visit costs

The page now says what it weighs in the world: **0.018 g CO₂ a visit, rating
A+**, from Website Carbon, for the 171 KB the home page actually transfers.

It is measured in `scripts/performance.mjs` rather than in the sync, because it
depends on the build and not on the time of day — a page's footprint changes
when the page changes, not when the clock moves. The arithmetic is theirs (the
Sustainable Web Design model and their coefficients), the bytes are Lighthouse's
`total-byte-weight` from the run the figure was taken from, and the footer
credits them by name, like every other fetched figure here. If they do not
answer, the previous number stands with its own date.

It sits beside "no analytics, no cookies, no third-party requests", which is
the right company for it: this is the same claim, expressed as a quantity that
someone else computed.

## About is gone

The page is now the hero, GitHub Projects, Achievements and Contact. The About
section held a paragraph of LinkedIn wording and the two degrees, and both are
said better elsewhere: the degrees are on the CV, which is the first thing the
hero offers, and the sentence about what he is doing now is in the hero's own
second line.

The degrees stay in `profile.ts` because `Resume.tsx` prints them. The

## The menu never marked the last section

Reported, reproduced, fixed. The indicator was an IntersectionObserver watching
a band across the middle of the viewport, and it could not light Contact:
Contact is shorter than that band, and at the bottom of the page — where the
scroll stops — the band lies over the footer, so no section is inside it at
all. A reader who got to the end saw nothing marked, which is worse than
marking nothing at all: the menu looks broken.

It reads position now. The current section is the last one whose top has passed
a line a third of the way down the viewport, and at the bottom of the document
it is the last section, because that is what the reader has arrived at whether
or not it is tall enough to reach the line. One passive listener, coalesced
into a frame; the section tops are measured on resize, not per frame.

A test holds it: scroll to the bottom, Contact is `aria-current`. That is the
case a person reported, so that is the case the suite now owns.

## The UI review, carried out

Nine findings from the review of 23 September, in three passes. What each one
cost and what it moved:

**The system.** Nine font sizes became five, declared once in `@theme` and far
enough apart to be told apart: 12 for what was fetched, 14 for the text, 16 for
a lead, 21 for a title, 34 for the name. Everything Tailwind ships above them is
`initial`, so a sixth size is a decision rather than an accident. The figure in
an entry, which was 27 px against its title's 21, is one step under the title:
a portfolio is scanned by name, and the eye was reading the numbers first. The
fetched signals gave back their green — a third hue for the least important
class of information on the page — and kept it only where the colour _is_ the
information, on a build that passed. The theme control stopped breathing.

**The first impression.** The hero led with a degree and never said what he
builds; it now opens with one sentence naming what the five projects under it
are, which a reader can check by scrolling. "Last updates" left the first
screen for the section it is about. The hero closes on its actions instead of
carrying a section's padding, and at 1440 the first project is now inside the
first screen, where the fold used to land in the gap. Contact answers the
question it is asked: "from when" was the second half of a sentence about
e-mail and is now the first line, in ink.

**The density, and the honest part.** The rail is gone. It was a window's
indicator and the window went away in the morning; since then it had been
saying what the browser's own scrollbar says, two centimetres to its left,
while the pills above already name the project in view. The covers are 16:9 on
a phone, and two of the six signals are hidden there.

That leaves the phone at **8.2 screens against the 5.9 the plan aimed at**, and
the measurement says why: `#work` is 4,261 px of the 6,908, and a single entry
is 514 px of which the picture is 181. There is no spacing left to take —
tightening everything that is not content bought 99 px. Getting under six
screens means **removing content on small screens**, and that is a decision
rather than a refinement:

- Three featured projects on a phone and two behind a control (−1,000 px).
- "Also on GitHub" as a native disclosure under 760 px (−400 px).

Both are one-line changes; neither is mine to make.

Two things the suite caught as the type came down, both the same rule: the
provenance links under the paper and the new update links fell to 18 px tall,
under the 24 px a target needs. WCAG 2.2's target size is the check that keeps
catching this, which is the argument for having kept it in a suite of eight.

## The sun and the moon break

Every press of the theme control switches the theme and does a little more
damage to what it shows: whole, cracked, broken in two. The third press puts it
back together, which is the joke, and also the only ending that does not leave
a visitor stuck with a ruin. Six presses are a full turn of both bodies.

The two glyphs are drawn here rather than imported, because the library has one
sun and one moon and both are in one piece — so this also took the last two
icons out of the bundle. The crack is not one drawing used twice: the sun's
disc is eight units across and the crescent is three times that, so each has
its own, at the same angle and with the same kink, which is what makes the
damage read as one idea. A break throws off two shards and takes rays with it.

It starts whole on every visit, which is what the prerendered HTML contains,
so there is nothing to hydrate around and the visual baseline stays
deterministic. The glyph is keyed by its condition, so React replaces it on
every press and the hit animation runs again; reduced motion removes the shake
and keeps the damage.

A unit test holds the whole cycle: six presses, six distinct glyphs, and the
seventh is the first again.

It is a small joke on a page with none, and that is the argument for it: a
portfolio that is correct everywhere and surprising nowhere is a document.

## Compact, cased, gold, and a borrowed line

Four things, on the same pass.

**The page stopped being spaced out.** The rhythm was set once, when sections
were far apart and entries were cards: `--section-gap` 36–56 px and
`--heading-gap` 16–22 px, with every entry at 24 px of padding and 8 px between
its parts. Now 26–40 and 12–18, entries at 20 px with 6 px inside, and the
column beside a picture at 8 px instead of 12. Nothing was removed and the
phone went from **6,908 px to 5,810**.

**The tail folds away.** "Also on GitHub" was six one-line pointers taking a
fifth of the section to repeat what the five entries above say better, and a
section that runs for a page and a half is one nobody reaches the end of. It is
a native `details` now, closed, with the count in its summary. A closed
`details` is markup, not an absence: the rows are in the HTML for a search
engine, a screen reader and the printed page.

**The picture has a case.** A clip with the browser's controls under it and
nothing around it reads as a video somebody dropped on a page. The same picture
in a window — a bar with three dots, a hairline, a shadow — reads as a program
that was run, which is what it is. It is the chrome the paper's first page
already sits in, so the two sections say "this is a program" and "this is a
document" in one grammar.

**The control is gold.** Solarized's yellow two steps down, 4.1:1 on the
surface: the red was a step too far into the alarm end of the palette for a
control that switches a preference.

Page height, phone: **8.2 screens this morning, 7.0 now**, with the same
content in the document.

## A window inside a window

The case around a picture went on every entry, and the paper's first page was
already in one: two title bars, stacked, in the same widget. It is the kind of
thing that is invisible while writing the rule and obvious the moment it is on
screen, which is the argument for looking at every change instead of trusting
the diff. The sheet's own chrome is gone and the case carries it, and with it
went the last rule in `paper.css`, so the file went too.

The page itself is softer: it fades out at its foot instead of being cut, so a
wall of six-point type reads as a page rather than as a screenshot, and it sits
at 95% opacity. Its provenance line under it is tighter by a few pixels.

**ZenQuotes is out.** A service that picks the sentence, a sync that commits it
every half hour and nobody reading it before it is live is three ways for
somebody else's words to end up under David's name. The page borrows nothing
now; every line on it is his, or is credited to a record he can point at.

## The index of five names is gone

It was a table of contents for a list you can see the whole of, and it scrolled
away exactly when a reader might have wanted it — which is the report that
retired it: _"sono inutili anche tenendo quello evidenziato, se poi scendendo
non li vedo più"_. Either it becomes a sticky bar, costing 40 px of a phone
screen for five links to five things already on the page, or it goes. It goes.

What replaces it is what was already true: the menu at the top marks the

## Everything outside the hero and Contact is extracted

The rule, given today: apart from the first screen and Contact, every word on
the page comes from the repository it is about or from the paper's record.

For the projects that meant three more things fetched. A project's **name** is
now the first heading of its README, read from raw.githubusercontent.com — a
static file, no token, no share of the hour's API allowance — because
`PPS-22-srs` is an identifier and the README knows the project is called the
Scala Robotics Simulator. Its **category** is its first two GitHub topics, its
**tags** are the rest of them (the first two are already the line above, and
the same words twice in two shapes is not information), and its **years** are
the repository's own created and pushed dates.

For the paper it meant the whole entry. Crossref carries the publisher's
deposit — title, journal, volume, article number, year, authors, citations —
and OpenAlex carries the abstract, as an inverted index that the sync puts back
into sentences and cuts at two. What went: the hand-written summary, the
category, the CRediT line, and "what I built", which was the one sentence on
the page where David described his own work. It belongs in the CV, which is a
document with a name on it; a page that says everything is sourced cannot make
one exception for the nicest sentence.

One consequence, visible immediately: the Scala Robotics Simulator is now filed
under `deep-learning / machine-learning`, because those are its topics. It
reads worse than "Robotics / reinforcement learning" did, and the fix is on
GitHub, where it also helps whoever finds the repository without the portfolio.
That is the rule working, not failing.

The sync also learned that a source which answers should not be skipped because
another one did not: the README is fetched even when the API has refused, so a
rate limit costs the fresh figures and not the names.
